За скобками данной статьи

Общие стандарт корп управления и управления человеческим капиталом, тк это справедливо для всех команд разработки. Например: принятие решений по данным, продуктивная корп среда и т.п. — не рассматриваем.

Что уже более менее понятно?

Как с точки зрения орг. дизайна выстроить работу платформенных структур. Тезисно их можно свести к следующему

  • Наличие процесса формирования планов на квартал и год, например PI Planning.
  • Платформенная работа распределяется между продуктовыми командами, “разбавляя” текущую деятельность.
  • При сложных контекстах могут временно создаваться “сборные” платформенные команды с понятными целями.

Основная сложность которая решается на первом этапе — необходимые и достаточные ресурсы для реализации платформы, без перегибов в обе стороны.

В чем сейчас основной фокус?

  • Создание законченных экосистем, для увеличения удобства и скорости разработки
  • CyberSec, включая вопросы лицензирования
  • Коммерциализация, включая новые формы монетизации
  • Преодоление технологической изоляции и нивелирование последствий ограничений

Современные вызовы для российских компаний

  • Использование генеративных ИИ в разработке
  • Вывод продуктов в Open Source и создание сообществ
  • Open Source Program Office (OSPO)
  • Создание консорциумов, для разделения затрат на разработку платформенных компонентов между несколькими коммерческими структурами

Примеры для направлений использования ИИ в разработке, где их помощь может быть очень продуктивной

  • Создание тестов в том числе Unit
  • Создание Release Notes
  • Генерация документации и поясняющих записок
  • Работа с Backlog
